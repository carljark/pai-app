PARTE II: ESPECIFICACIONES TÉCNICAS (El Tech Stack)
Para el desarrollador, estas son las tecnologías de código abierto más recomendadas actualmente para construir plataformas EdTech (Tecnología Educativa) con Inteligencia Artificial:
1. Frontend (La interfaz visual que ve el docente)
	•	Framework: React.js (utilizando Next.js) o Vue.js (Nuxt.js). Son los estándares de la industria, rápidos y escalables.
	•	Estilos: Tailwind CSS. Permite hacer interfaces muy limpias y modernas rápidamente.
	•	Editor de Texto: Integrar una librería como TipTap o Slate.js para que el "Lienzo Central" del Taller de Proyectos funcione por bloques editables de forma fluida.
2. Backend (El servidor y la lógica)
	•	Lenguaje: Python. Es absolutamente obligatorio que el backend esté en Python, ya que es el lenguaje rey de la Inteligencia Artificial.
	•	Framework: FastAPI. Es ultrarrápido y perfecto para gestionar las peticiones entre la base de datos, la IA y el Frontend.
3. Bases de Datos
	•	Relacional (Para los currículos y usuarios): PostgreSQL. Aquí irán los archivos CSV que hemos creado con los Módulos, RA y CE.
	•	Vectorial (¡Crucial para la IA y el Repositorio!): El informático debe instalar la extensión pgvector en PostgreSQL o usar una base de datos vectorial separada como ChromaDB. ¿Por qué? Porque las IAs no leen bases de datos normales, leen "vectores" para entender qué proyectos del repositorio se parecen más a lo que el profesor está pidiendo.
PARTE III: INTEGRACIÓN DE LA IA GENERATIVA (Arquitectura RAG)
Esta es la parte donde la magia ocurre. Dile a tu informático que la plataforma debe utilizar una arquitectura RAG (Retrieval-Augmented Generation) impulsada por el framework LangChain.
El flujo exacto de programación debe ser este:
	•	El Input del Usuario: El profesor elige "Ciencias" y "Peluquería" y pulsa "Generar".
	•	El Retrieval (Recuperación): El backend en Python busca en la base de datos vectorial (el Repositorio de proyectos validados) si algún otro profesor ya hizo un proyecto de Ciencias + Peluquería.
	•	El Prompting (Ensamblaje): LangChain coge:
	•	El Prompt de Sistema (las reglas pedagógicas inquebrantables que definimos antes).
	•	Los RA y CE seleccionados de los CSV.
	•	Los proyectos similares encontrados en el Repositorio.
	•	La Generación (LLM Local): Se le envía todo ese paquete de información al Motor de IA.
	•	Recomendación de Modelos Locales: Utilizar modelos de código abierto como Llama 3 (Meta) o Mistral.
	•	Ejecución Local: Se pueden correr en el servidor local del instituto usando herramientas como Ollama o vLLM, lo que garantiza que los datos no viajan a internet.
PARTE IV: CONSEJOS CLAVE PARA EL DESARROLLO (Buenas Prácticas)
	•	Estrategia MVP (Producto Mínimo Viable): Montar una IA local (Llama 3) desde el día 1 requiere servidores con tarjetas gráficas (GPUs) potentes y mucho tiempo de configuración. Dile a tu informático que en la Fase 1 conecte la plataforma a la API de OpenAI (ChatGPT) o Anthropic (Claude). Una vez que la plataforma funcione, los botones hagan clic y los profesores la validen, entonces haced el "desenchufe" y migrad a la IA local para la Fase 2 de tu tesis.
	•	Cumplimiento RGPD (Privacidad por Diseño): Al diseñar la base de datos, aseguraos de que en ningún momento se introduzcan nombres, apellidos o datos médicos de los alumnos reales en el asistente de IA. La IA solo debe procesar texto del currículo oficial y actividades.
	•	Exportación a GestIB: Que el informático estudie en qué formato de Excel o CSV importa las notas el sistema GestIB (el sistema educativo balear). Si la plataforma genera un Excel con las columnas exactas que requiere GestIB, los docentes os adorarán, ya que les ahorraréis horas de pasar notas a mano.
